# 念佛计数 App —— 需求与设计（定稿 v1.5）

> 本文件是产品需求与设计的完整总结，与《App 简易线段UI.md》配套，
> 可直接交给开发团队 / coding agent 实施。
> 戒指硬件与固件不在本文件范围内（仅定义交互边界）。
>
> v1.1 修订要点（依据外部评审）：
> 1. 手动填报成为一等公民：首页直接入口；计入个人统计、每日目标与个人大愿。
> 2. 戒指/手机两个计数上下文各自独立（各有当前功课与本轮），首页页签只是切换查看对象。
> 3. 戒指同步采用"按天存、按键覆盖、不追加"模型，多戒指合并、重复同步不会重复加数。
> 4. 修正按来源删减；原始同步数与本地修正分开保存，同步永不覆盖修正。
> 5. 戒指即时操作改为"戒指确认后才算成功"，过期提醒不补发。
> 6. 零点只切日统计，不强制结束本轮与提醒目标。
> 7. 每日目标保留历史生效口径（归档时快照目标）。
>
> v1.2 修订要点（第二轮评审 + 用户决策）：
> 1. 清空戒指不再使历史作废：epoch 只用于区分新旧归属，已同步的历史始终保留并参与统计。
> 2. 快照覆盖前先比较 version：新覆盖旧、相同忽略、旧版本拒绝，防止乱序数据倒退。
> 3. 丢失绑定凭据 ≠ 戒指属于别人：显示"无法验证原绑定关系"，可经云账号/备份恢复重连；仅真实转让才清空换绑。（v1.3 已放宽为接力/转让均可由新手机直接绑定并清空，并移除原拟的长按戒指 8 秒物理确认）
> 4. 目标快照补齐流程：修改目标默认次日生效，修改前先补齐截至今天的快照（含零计数日）。
> 5. 数据保管承诺升级：凡同步过一次的数据由 App + 服务器负责保管，删除 App / 格式化戒指 / 换手机后，重新下载登录仍可找回全部历史。（开启前提在 v1.4 修正为：注册登录后才云同步）
>
> v1.3 修订（用户决策）：戒指接力/转让极简化——戒指归最后绑定者，家人/他人手机直接绑定并清空（仅提醒"将清空戒指内数据"即可）；原用户已保存的历史不受影响（未注册时保存在原手机，注册后由云端保管）；移除"原手机确认"与"长按 8 秒物理确认"步骤。
>
> v1.4 修订（用户决策）：云同步以注册为前提——不注册不登录则纯本地保存（删 App 即丢失，UI 明确提示并引导注册/导出备份）；注册登录后自动开启云同步，此后数据由 App+服务器保管。
>
> v1.5：补充「§11 云端最小闭环设计」（注册/登录流程、与本地同构的同步单元、按键 upsert + version 合并规则、服务端最小接口、隐私归属）；新增 P17 登录/注册页，页面口径统一为三 Tab 页 + 17 子页 + 3 弹层（共 20 页 + 3 弹层）。

## 1. 产品背景与目标

**现状痛点**（主流产品：缘渡、一心等按键计数器）：
1. 缺乏智能化：不能自动按日归档，用户需借助其他 App 手动登记。
2. 不够隐蔽：套在手指上体积大，公共场合/工作场所高调。
3. 不防水。
4. 按键寿命约 500 万次，日课 3 万的重度用户很快用坏。
5. 现有修行计数 App 设计简陋，部分还收会员费、打广告，甚至有欺骗老年修行人的嫌疑。

**产品方案**：
- 以智能戒指为载体，去除多余传感器，只保留触摸模块 + 蓝牙。
- 两款戒指：**有屏款**（戒指上可看计数、切功课，屏幕按需点亮不长亮）与**无屏款**（戒指只计数，其余全在 App 侧）。
- 戒指 + App 组合覆盖修行计数场景；**App 永久免费、无广告**，戒指销售收入支撑 App 运营。
- **没有戒指的用户（手机计数 + 手动填报）也能完整使用全部统计功能**——填报是一等使用路径，不是附属功能。

**设计原则**：
1. UI 简洁明了，老年修行人一看就懂。
2. 戒指与 App 交互足够简单。
3. 戒指计数、手机计数、手动填报在个人统计中地位平等；来源标记全程留痕。
4. 数据可信且可解释：用户每天记下的数据，几年后仍然准确、可解释、可找回。

## 2. 核心概念模型

```
功课 Practice（顶层实体，如：南无阿弥陀佛 / 阿弥陀佛 / 禅坐）
├─ 公共功课：系统预置，带别名描述；自建功课：搜索无匹配时创建
├─ 类型：计数型（单位：声/遍/座…）｜ 计时型（禅坐类，锁计数只计时）
├─ 每日目标（默认 108，归档时快照，修改不影响历史）
├─ 震动提醒（无/100/108/自定义）· 我的显示名（选填）· 首页显示开关
│
├─ 计数上下文 CountContext × 2（戒指侧、手机侧，各自独立）
│   {当前功课, 起始时间, 本轮计数, 提醒目标?}
│   戒指离线独立工作；手机在木鱼页独立工作；互不干扰
│
├─ 开启新一轮计数（作用于某一侧上下文）
│   = 切到该功课 + 本轮清零 + 可选提醒目标（30分钟/500声）
│
├─ 今日累积：戒指 + 手机 + 手动填报 三来源合计，每日 0 点归档
│
└─ 大愿 Vow：长期目标，按日归档累加；个人大愿计入全部有效来源
   （含手动填报）；未来共修排行另行制定来源口径（首版不实现）
```

**用户心智：数会自动记；想专心念一会儿，"开启新一轮计数"时顺手选个目标；用传统计数器念的，每天填报一下。**

## 3. 关键设计决策

| 决策点 | 最终结论 |
|--------|----------|
| 数据层级 | 扁平化：只有"功课"一层 |
| 早晚课 | 不做。未来如需，以"定时提醒目标"形态加回 |
| 原“一座/专念”场景 | 不独立归档，合并进「开启新一轮计数」（订闹钟语义） |
| 计数上下文 | **戒指、手机各自独立**保存当前功课与本轮状态；首页页签只切换查看对象；不保存每座历史 |
| 手动填报 | 一等使用路径：首页直接入口，默认今天，可连续填多个功课；**计入个人统计、每日目标与个人大愿**；未来共修另行制定来源规则 |
| 填报 vs 修正 | 分开表达：填报=登记"本次新增数量"（手动来源，可撤销）；修正=纠错（按来源删减） |
| 计数流水 | 不记事件流水。戒指按"日×功课"存快照；App 落每日归档 + 分来源修正记录 |
| 戒指同步 | 按天存记录、App 按键覆盖不追加（见 §6）：覆盖前比较 version（新覆盖旧/同忽略/旧拒绝）；多戒指按设备分开存再汇总；戒指不删已同步记录 |
| 修正账目 | 原始同步数与本地修正分开保存；删减必须标明来源（戒指/手机）；撤销修正=恢复该修正，不产生新补录 |
| 跨天计数 | 零点只切日统计；本轮与提醒目标**跨零点继续运行**（睡前 23:50 开 30 分钟，00:20 正常提醒） |
| 每日目标历史 | 归档时快照当日目标；**修改目标次日生效**，修改前先补齐截至今天的快照（含零计数日）；隐藏/删除不影响历史；未来日期不算未完成；无目标功课不参与"全部达标" |
| 戒指离线操作 | 配置类可"待同步"；实时类（新一轮/切功课/清零/提醒/锁定）**须戒指确认才显示成功**；过期提醒不补发 |
| 多戒指与接力 | 一用户可绑多枚；一戒指同时只绑一个用户，**归最后绑定者**；家人/他人手机直接绑定并清空即可（仅提醒，无需原手机操作）；原用户已保存的历史不受影响（未注册时保存在原手机，注册后由云端保管）；自己的戒指重装后如仍能恢复绑定凭据（云账号或本地备份）可免清空找回；epoch 区分新旧归属，历史永不作废 |
| 数据保管 | 未注册：数据仅保存在本机（可导出备份，删 App 即丢失，UI 明确提示）；**注册/登录后开启云同步**：此后数据由 App+服务器保管，删除 App/格式化戒指/换机后登录即可找回 |

## 4. 功能需求清单

### 4.1 计数（双上下文）
- 戒指触摸计数、手机木鱼点按，各自维护独立的计数上下文（当前功课 + 本轮计数）。
- 两侧计数都实时计入该功课今日累积（带来源标记）。
- 首页页签（戒指计数/手机计数）= 切换 LED 区与累积数字的查看对象。
- 开启新一轮计数：选择作用于哪一侧（戒指/手机），该侧切功课 + 清零本轮 + 可选提醒目标。
- 计时型功课（禅坐）：只计时，"开启新一轮"= 开始计时；归档记当日时长与次数。

### 4.2 提醒目标
- **首版仅在"开启新一轮计数"时可设**：15/30/60 分钟 或 108/500/1000 声（二选一，记住上次）。
- 语义明确：从本轮起点算，到时长 / 本轮再计满 N 声时提醒。
- 戒指侧目标下发闹钟（需戒指确认）；手机侧目标用 App 本地提醒。
- 到点：震动 + 通知「目标达成，本次念了 N 声」→ 目标自动清除；计数继续。
- 取消提醒只取消闹钟；目标生效中在该侧切功课/重新一轮需确认「将取消本次提醒」。
- **提醒目标跨零点继续有效**，不随日切丢失。

### 4.3 首页
- LED 数码管大字 = 当前查看侧（跟随页签）的本轮计数；小字标来源。
- 小字行：今日累积（跟随页签来源口径）。
- ◀▶ 切换当前功课；锁定按钮与同步状态作用于当前戒指（多戒指时可切换）。
- **填报直接入口**：「✎ 填报今日数据」（见 4.4）。
- 提醒目标生效时显示状态横幅，点进功课详情。

### 4.4 手动填报与修正（分开两件事）

**填报（日常使用）**：
- 入口：首页「✎ 填报今日数据」→ 弹层：选功课 → 填「本次新增数量」→ 保存 / 保存并继续填报（连续填多个功课）。
- 日期默认今天，可补填过去日期。
- 填报记为手动来源，计入今日累积、每日目标进度与个人大愿。
- 填报记录可撤销（撤销=移除该笔填报，不产生反向账目）。

**修正（纠错用）**：
- 入口：日历 → 当日详情 → 点功课行 → 修正。
- 纠正误触：选择戒指或手机来源进行删减（必须标明减哪个来源）。
- 界面引导用户把误触来源的数量调低，底层记为分来源的修正记录。
- 如需增加数量，回到「填报」入口按手动来源登记，不在修正中生成新增记录。
- 撤销一笔修正 = 恢复该修正，不产生新账目。

### 4.5 每日归档与日历
- 每日 0 点归档：按事件发生日期切分（23:50 的计数归昨天，00:10 的归今天）；戒指 RTC 翻篇生成日记录。
- **每日目标快照**：归档时快照当日目标；**修改目标默认次日生效**——修改/停用功课前先补齐截至今天（含零计数日）的目标快照；后续补归档与同步只更新数量，绝不覆盖已有目标快照。
- 归档字段含来源拆分：戒指（按设备汇总的原始同步数）、手机、手动，以及分来源修正。
- 日历月视图：「查看」选择器切换 全部功课 / 单个功课。
  - 全部：格内达标标记（●◐○·）。无每日目标的功课不参与"全部达标"判断。
  - 单功课：格内显示当日总数，未达标日标色；底部本月达标天数与日均。
- 当日详情：各功课累积 + 来源拆分（含填报记录）；点行进修正。

### 4.6 长期大愿
- 基于某功课发愿：目标总数 + 可选期限 + 可选开始日期（默认明天；选过去则汇总已有归档）+ 可选"已有累计"（承接他处进度）。
- **个人大愿累加计入全部有效来源：戒指 + 手机 + 手动填报**。
- 未来共修/排行（首版不做）另行制定来源口径，不影响个人大愿。
- 展示：累计/百分比/日均/预计圆满/近 30 日趋势；圆满显示「已圆满 🎉 历时 N 天」可再发新愿。

### 4.7 功课管理
- 公共功课库模糊搜索（别名命中）；无匹配 → 自建功课。
- 功课分**计数型**（单位可选 声/遍/座 等）与**计时型**（禅坐类，锁计数）。
- 新建默认每日目标 108（按类型给合理默认；无目标的功课只统计不参与达标判断）。
- 功课设置：每日目标、震动提醒、首页显示、删除；公共功课实名固定，可设"我的显示名"（仅自己界面显示）；「锁计数」仅计时型显示。
- 修改目标/隐藏/删除不影响历史统计与历史达标判断。

### 4.8 设备（戒指，支持多枚，归最后绑定者）
- 一个用户可绑多枚戒指；一枚戒指同一时间只绑一个用户。
- **接力/转让（归最后绑定者）**：家人或他人的手机直接绑定即可——检测到戒指已绑定其他用户时，提示「继续绑定将清空戒指内的全部数据（含尚未同步的计数），原用户的 App 数据不受影响」→ 确认 → 清空（生成新 epoch）→ 绑定完成。无需原手机任何操作，无需物理确认。
- **接力使用建议**：交还/转借前各自在 App 同步一次，未同步的计数才会进入自己的 App 数据。
- **找回自己的戒指**：重装 App 后，若已通过云账号或本地备份恢复 owner_token，且戒指仍绑在自己名下（未被他人绑定），可直接重连，无需清空。
- **原用户侧**：App 下次连接发现戒指已被他人绑定（token 不匹配/epoch 变化）→ 提示并可选择"重新绑定"（走清空流程）或"移除设备"；历史数据不受任何影响。
- 全局一个"当前戒指"：LED 区、锁定、同步状态、戒指侧开启新一轮均作用于它。
- 断连期间戒指本地计数不丢，重连按快照模型同步。

### 4.9 其他
- 手机计数设置：音效、震动反馈、外观、撤销确认。
- 计数入口设置：戒指/手机可分别关闭，**也可全部关闭（纯填报模式）**——此时首页隐藏计数区与页签，保留功课列表与填报入口。
- 计数汇总：各功课历史累计 + 来源拆分 + 修行天数；计时型显示累计时长与次数。
- **数据保管（登录后云端）**：未注册不云同步，数据仅保存在本机——「我的」页游客卡片明确提示，并引导注册或导出备份；**注册/登录后自动开启云同步**，此后数据由 App + 服务器负责保管：删除 App、格式化戒指、换手机后，重新下载并登录即可找回全部历史。本地导出/导入恢复（含校验）保留为兜底；设置页含「备份 / 恢复」入口。
- 独立早起闹钟：待定（若做，独立于计数操作，不因切功课/重新一轮而取消）。

## 5. 数据模型

```
practice          功课：id, name(实名), display_name(我的显示名,可空),
                  公共/自建, 类型(计数/计时), 单位(声/遍/座/分钟),
                  别名描述, 每日目标(当前值), 震动提醒, 首页显示, 排序,
                  创建时间, 是否删除
                  ※ 目标历史不存版本表——归档时已快照，见下

daily_archive     每日归档：日期, practice_id,
                  ring_raw(戒指原始同步合计), phone_raw(手机原始合计),
                  manual_total(手动填报合计),
                  target_snapshot(归档时的每日目标快照),
                  duration_min, times(计时型：当日时长与次数),
                  展示总数 = ring_raw + phone_raw + manual_total + Σadjustment

adjustment        修正记录：id, 日期, practice_id, 来源(ring/phone),
                  delta(恒为负), 创建时间
                  ※ 填报不是 adjustment；填报直接计入 manual_total（可整笔撤销）
                  ※ 同步只更新 *_raw，永不触碰 adjustment

device_day_snapshot  戒指日快照（同步核心）：
                  device_id, epoch(数据代次), 日期, practice_id,
                  total(该设备当日总数), version
                  ※ 同键更新先比较 version：新覆盖旧、相同忽略、旧版本拒绝；
                    epoch 在设备清空后重新生成（可为随机代次，不要求清空后保留旧值），
                    只用于区分新旧归属——已同步的旧 epoch 历史始终保留并参与合计；
                    ring_raw = 该戒指各 epoch 快照之和（多戒指再相加）

count_context     计数上下文 ×2（ring / phone 各一条，持久化）：
                  side, practice_id, start_ts, round_count,
                  提醒目标{类型, 值, 起始基数}?

vow               大愿：id, practice_id, 名称, 目标总数, 开始日期,
                  期限?, 已有累计?, 状态
                  ※ 累计口径 = 全部有效来源（含手动填报）

device            戒指（多条）：id, 名称, 型号, 固件, 电量, 锁定状态,
                  可切功课顺序, 屏幕点亮方式, 最后同步时间,

settings          计数入口(戒指/手机，可全关=纯填报), 音效/外观, 通知, ...
```

## 6. 戒指端存储与同步协议

### 戒指端存储

```
日快照:   [日期][功课ID][当日总数][version]   ← RTC 每日 0:00 翻篇生成
本轮状态: 当前功课ID + 本轮计数（+进行中的提醒目标进度）
          ※ 翻篇只生成日快照，本轮计数与提醒目标跨零点继续
归属:     owner_token（绑定时写入；清空设备时一并清除）
容量:     快照约 8–12 字节/条（体积估算；固件须实测验证断电持久化
          与存储写满后的淘汰策略，列入验收清单）
```

### 同步模型（一句话：按天存、按键覆盖、不追加）

设计模型就是用户的直觉模型：
- 戒指按"日期×功课"保存每日总数；0 点封盘后，历史记录不再变化。
- App 拉取记录后按（戒指, 日期, 功课）**覆盖保存**——同一天的记录再次同步只是覆盖旧值，绝不累加。这就是"重复同步不会重复加数"的全部内容，没有额外协议。
- 覆盖前先比较 version：**较新版本覆盖、相同版本忽略、较旧版本拒绝**——防止乱序到达的数据把 120 覆盖回 100。
- 只有"今天"的记录会在 0 点封盘前被新值不断覆盖。
- 戒指不因为"已同步过"就删除记录（存储足够）：在仍能验证绑定凭据（云账号或备份恢复）时，换手机/重装 App 后可从戒指重新拉取恢复。

仅两个保护性字段，各有明确防坑场景：
- **device_id**：多枚戒指各存各的记录，App 按戒指汇总。少了它，戒指 A 和戒指 B 同一天的记录会互相覆盖（或变成重复相加）。
- **epoch（数据代次）**：戒指清空换绑后重新生成新值（可为随机代次，无需在清空后保存旧计数器）。它只用于区分新旧数据、防止清空后新生的"10月21日 = 50 声"覆盖掉清空前真实的"10月21日 = 800 声"；**已同步的旧 epoch 历史永远保留并参与统计**——清空戒指不会让用户的历史减少；戒指换主人后，新用户只接收新归属（新 epoch）下的数据。

云端保管：**登录后**，同步到 App 的数据自动上云；戒指与手机只是采集端。未登录时数据仅存本机，删除 App 即丢失（UI 需明确提示并引导注册/导出备份）。

### 操作分级（离线行为）

| 操作 | 行为 |
|------|------|
| 名称/排序/显示名等配置 | 可保存为"待同步"，连接后下发 |
| 戒指侧：开启新一轮 / 切功课 / 清零 / 设提醒目标 / 锁定 | **收到戒指确认后才显示成功**；未连接时明确提示"戒指未连接" |
| 过期的临时提醒 | 不自动补发 |
| 重新连接 | 先读取戒指实际状态与日快照，再处理待同步配置 |

- 「切功课＋清零＋设提醒」作为**一次完整操作**下发与确认（带操作 ID），避免只执行一半；同一操作重试不得再次清零（幂等）。

### BLE 指令清单（App → 戒指）

```
1. 对时             连接后必做
2. 下发功课列表+顺序
3. 切换当前功课
4. 本轮清零
5. 下发提醒目标闹钟（时长或次数）
6. 取消闹钟
7. 锁定 / 解锁触摸（戒指侧长按触摸区 3 秒兜底解锁）
8. 震动提醒配置（每 N 次）
9. 拉取日快照（带 version 增量拉取，按键替换）
10. 屏幕点亮方式（有屏款）
11. 写入/校验 owner_token
12. 清空全部数据（接力/转让确认后执行；生成新 epoch）
```

## 7. 规则汇总

1. **计数**：点按 → 所属侧上下文本轮 +1 + 该功课今日累积 +1（带来源标记）。
2. **双上下文**：戒指/手机各自独立；首页页签只切换查看对象。
3. **开启新一轮** = 作用于某一侧：切功课 + 本轮清零 + 可选提醒目标；戒指侧需戒指确认。
4. **提醒目标**：仅开启新一轮时可设；从本轮起点计算；跨零点继续；到点自动清除。
5. **填报**：首页直接入口，填"本次新增数量"，记手动来源，计入今日累积/每日目标/个人大愿；可整笔撤销。
6. **修正**：纠错专用；删减必须指定来源（戒指/手机）；原始同步数与修正分开保存；同步永不覆盖修正；撤销修正=恢复。
7. **归档**：每日 0 点按事件日期切分；归档时快照当日目标；App 未开则启动补归档。
8. **目标历史**：修改/隐藏/删除功课不影响历史达标判断；未来日期不算未完成；无目标功课不参与"全部达标"。
9. **个人大愿**：按归档累加全部有效来源（含手动填报）；共修口径后定。
10. **多戒指与接力**：一用户多戒指、一戒指一用户（归最后绑定者）；当前戒指全局唯一；家人/他人手机可直接绑定并清空（仅提醒，无需原手机操作）；自己的戒指在云账号或本地备份恢复凭据后可免清空找回；清空只影响戒指本地未同步数据，任何一方已保存的历史都不减少。
11. **同步**：按（戒指, 日期, 功课）覆盖保存、绝不追加；覆盖前比较 version（新覆盖旧/同忽略/旧拒绝）；多戒指分开存再汇总；戒指不删已同步记录；epoch 只区分新旧归属，已同步历史永不作废。
12. **离线分级**：配置类待同步；实时类须戒指确认；过期提醒不补发；重连先读戒指状态。
13. **日历**：可按全部/单功课查看；单功课口径格内显示当日总数，未达标标色。
14. **数据保管**：未注册仅存本机（UI 明确提示 + 可导出备份）；注册/登录后自动开启云同步，数据由 App+服务器保管，重装/换机登录即找回；本地导出/导入恢复兜底。

## 11. 云端最小闭环设计

### 11.1 账号与登录
- 轻量注册/登录：手机号 + 短信验证码（主），邮箱（备）；首版不设密码。
- 不强制注册：游客纯本地使用，UI 明确提示"数据仅存本机"。
- 登录/注册页见《App 简易线段UI》P17。
- 首次登录：本机已有数据自动上传，与云端按规则合并；此后自动开启云同步。
- 登录后：「我的」显示账号与同步状态；设置页提供退出登录、注销并删除云端数据入口（二次确认）。

### 11.2 同步单元（与本地同构）
云端表与本地一一对应；全部云端记录归属 user_id，每条记录带 version + updated_at：
- daily_archive（日期, practice_id）
- device_day_snapshot（device_id, epoch, 日期, practice_id）
- adjustment（只增；撤销 = tombstone 标记，不物理删除）
- practice / vow / device 元数据 / settings
- 戒指 owner_token 随账号保存（换机后凭此免清空找回戒指）

### 11.3 合并与冲突规则（与戒指同步同一心智：按键 upsert、比较版本、绝不追加）
- 同一主键：version 新者胜、相同忽略、旧者拒绝。
- adjustment 只增不删（撤销 = tombstone），天然无冲突。
- 目标快照（target_snapshot）只写一次，永不覆盖。
- 同一账号多台手机：按同一规则双向合并；服务器是保管方，本地是工作副本。
- 首次登录：本机数据全部推上云端；云端已有数据按规则合并下行。

### 11.4 同步方式
- 登录后自动开启；增量拉推（客户端记录 since-token，断网积攒、联网补传）。
- 同步失败不影响本地使用；恢复网络后自动续传。

### 11.5 服务端最小接口
```
POST /auth/code        发送验证码（手机号/邮箱）
POST /auth/login       验证码换访问令牌（新用户自动注册）
POST /sync/push        批量上行（记录数组，按键 upsert；返回新 since-token）
GET  /sync/pull        增量下行（?since=token）
GET  /account/export   全量导出（与本地备份同格式）
POST /account/delete   注销并删除全部云端数据（二次确认）
```
全部走 TLS；令牌支持刷新。

### 11.6 隐私与归属
- 数据归用户所有：可随时导出，可注销并删除全部云端数据。
- 手机号/邮箱仅用于登录与找回，不作他用。
- 未来共修/排行如需使用用户数据，单独征得同意并只取约定来源。

## 12. 联调验收场景（进入真实联调前必须全部通过）

| 场景 | 期望 |
|------|------|
| 同一快照同步多次 | 总数不变（覆盖而非累加） |
| 先收到新版本再收到旧版本 | 总数不倒退（旧版本拒绝覆盖） |
| 清空、重绑戒指 | 原用户已保存的历史不减少；新 epoch 数据另起归属 |
| 修改或撤销填报 | 日历与个人大愿同步更新 |
| 23:50 开始 30 分钟提醒 | 00:20 正常提醒；数量按事件时间分别归入两天 |
| 开始指令成功但回执丢失 | 重试不会再次清零（操作 ID 幂等） |
| 戒指断开手机 | 已设置的提醒仍在戒指侧正常执行 |
| 备份后恢复 | 数量、目标历史快照、修正记录完全一致 |
| 删除 App 重装并登录 | 云端历史完整找回 |
| 修改每日目标 | 次日生效；历史日期达标判断仍用当日快照 |
