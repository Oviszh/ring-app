# 本地记录版 · 发布前验收

> 历史验收记录。后续需求已恢复设备计数与 LED 显示，当前范围以《双计数入口-v1.0.1》为准；本文件中的旧截图、旧二维码及测试结果不代表当前改动已统一验收。

验收日期：2026-10-24。代码版本：1.0.0（候选版）。

本轮已完成界面与交互优化、自动化回归、微信本机模板和样式编译。当前可进入真机验收，尚未提交微信审核或发布。

## 本轮范围

原生微信小程序，提供手机计数、静坐计时、手动记录、日历、来源修正、长期大愿、累计记录、本地文件备份与恢复。按用户已确认的范围，首发界面不开放戒指、微信登录或云同步。历史戒指来源数据和领域逻辑保留。

## 界面与文案

- 全局采用纸白底色、松墨色主操作、细边线和适量留白，取消原首页花饰、回纹和金色渐变。
- 宋体用于主要功课名称和页面标题，正文与数字使用系统字体；主要操作保留较大点击区域。
- 首页分开表示本轮计数与当日累计，功课进度集中为列表。
- 手机计数页独立显示计数、今日进度、计数触摸区、音效和本轮操作；静坐采用单独的计时界面。
- 日历、详情、我的、大愿、表单与设置使用统一视觉。发愿表单按目标、累计起点、期限分组。
- 移除未实现的登录和云同步按钮、模拟设备入口。补充本机保存说明及隐私与数据页面。
- 将“实名显示”“下一阶段开放”、内部账目术语和冗长规则改为用户能直接理解的说明。
- 次要文字在纸白背景上的对比度约 4.59:1；主操作文字与深色背景约 8.96:1。

## 修复和补齐

1. 首页浏览其他功课时保留实际计数上下文；真正开始另一功课前再确认。
2. 从功课详情继续计数时保留本轮，开启新一轮单独操作。
3. 统一手动记录弹层，正确区分计数单位和静坐分钟，提供校验及连续填报。
4. 首页、功课详情和历史日期详情均可记录；全部功课隐藏时仍可手动记录。
5. 保存记录保持提交锁，避免快速重复点按造成重复入账。
6. 静坐结束后，从设置返回不会自动开始下一座；计时页拒绝点按计数。
7. 静坐可保留上次时间提醒偏好，禁止沿用次数提醒。
8. 按来源修正继续保留戒指/手机选择；修正恢复文案明确只加回这一笔扣除量。
9. 日历使用紧凑数字，避免较大数量挤出单元格；新建功课始终有直接入口。
10. 导入备份前保留本机副本，并提供查看、核对和恢复入口；恢复静坐副本时不把等待期间计入时长。
11. 计数页启用前台常亮，离页关闭并释放音频资源；重新静坐时恢复常亮。
12. 解决微信 style v2 原生按钮默认宽度覆盖页面样式造成的挤压、竖排和布局溢出。

## 与原定稿的调整

| 原定稿/既有实现 | 本轮实现及依据 |
| --- | --- |
| 双端入口、设备绑定和游客登录卡片 | 用户要求先做好无戒指本地版，暂不开放这些入口 |
| LED 数码管、莲花花饰、金色卡片 | 当时实现将这些一并简化；用户随后明确要求恢复 LED 数码管，已在 v1.0.1 补回 |
| 首页左右切功课立即结束本轮 | 改为先浏览、开始时确认，避免查看造成误清零；统计规则不变 |
| 填报只在首页 | 增加详情及历史日期入口，复用同一业务写入和校验 |
| 导入前副本只保存在存储中 | 增加实际可用的恢复入口，并防止恢复时虚计静坐时长 |

数据正确性红线保留：来源留痕、快照按键和版本覆盖、历史目标快照、次日生效、填报与修正分离、跨日计数和提醒、删除后历史保留、计时型只计时。
