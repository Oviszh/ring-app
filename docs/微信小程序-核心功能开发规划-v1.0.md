# 念佛计数微信小程序 —— 核心功能开发规划 v1.0

日期：2026-10-22  
依据文档：

- `App-需求与设计.md`（定稿 v1.5）
- `App-简易线段UI.md`（定稿 v1.5）
- `定稿检查报告.md`

本规划是在最新产品决策后的执行版：**先做微信小程序；暂缓 Android / iOS App；不做戒指介绍、预约/定金预售、问卷、社群入口；不做共修、排行、早晚课。**

---

## 1. 首版目标

做一个可以真实使用的微信小程序核心版本：

1. 没有戒指的用户，可以用「手机计数 + 手动填报」完整记录修行。
2. 有戒指的用户，可以绑定戒指、同步戒指计数、锁定戒指、下发提醒目标。
3. 数据可以本地使用；用户主动微信登录后开启云同步。
4. 所有统计口径与定稿一致：戒指、手机、手动填报三类来源平等，来源全程留痕。
5. 小程序不能承诺后台常驻，因此产品模型固定为：**戒指离线工作，小程序打开时同步。**

## 2. 范围边界

### 2.1 首版要做

- 三 Tab：今日、日历、我的。
- 手机计数（木鱼式大触摸区）。
- 手动填报、撤销填报。
- 修正戒指/手机误触数量。
- 功课管理、添加公共功课、自建功课、功课设置。
- 每日目标、目标历史快照、达标判断。
- 月日历：全部功课 / 单功课查看。
- 个人大愿。
- 计数汇总。
- 微信登录、云同步、账号与同步状态。
- 戒指绑定、单枚戒指页、戒指同步、锁定、切换功课、提醒目标。
- 多戒指列表、当前戒指切换，以及按设备分开保存再汇总。

### 2.2 首版不做

- Android / iOS App。
- 戒指介绍、预约、定金预售、问卷、社群入口。
- 共修、排行、同修数据参考。
- 早晚课。
- 经文原文与拼音。
- 社交化账号功能。
- 独立早起闹钟。
- 手机侧后台提醒。

### 2.3 小程序平台降级口径

| 能力 | 小程序首版口径 |
|---|---|
| 手机计数 | 仅小程序前台可用；切后台后不承诺继续计时/提醒 |
| 手机侧提醒目标 | 仅前台倒计时提醒；UI 必须明确提示 |
| 戒指侧提醒目标 | 正常下发到戒指，由戒指离线执行 |
| 戒指计数 | 戒指离线独立完成；小程序打开后同步 |
| 本地备份导出 | 首版可延后；优先做微信登录后的云同步 |
| 账号体系 | 游客本地使用；用户点击「微信登录开启云同步」后上云 |

## 3. 技术选型

### 3.1 小程序端

- **原生微信小程序：WXML + WXSS + JavaScript**。
- 新项目不引入 Taro / uni-app，减少构建与调试复杂度。
- UI 组件自行实现，保持老年用户可读性：大字号、大按钮、高对比。
- 本地缓存使用 `wx.setStorageSync / wx.getStorageSync`。
- BLE 使用微信小程序原生蓝牙 API。

### 3.2 云端

首版推荐使用 **微信云开发**：

- 云数据库保存用户数据。
- 云函数作为唯一数据写入入口，前端不直接写核心业务表。
- 所有合并、version 判断、目标快照保护都在云函数内完成。
- 后续若恢复 Android / iOS App，可把云函数包装成 HTTPS API，或迁移到自有后端；数据模型不变。

### 3.3 分层结构

```text
pages/                  页面
components/             通用组件
services/
  domain/               功课、归档、目标、大愿、修正等纯业务逻辑
  storage/              本地缓存与本地 outbox
  cloud/                云函数调用封装
  ble/                  BLE 抽象层
    mock-adapter.js     模拟戒指，供无硬件开发
    wechat-adapter.js   微信小程序真实 BLE
utils/
```

原则：**页面不直接操作数据库，页面只调用 domain / service。**

## 5. 数据模型

云端与本地尽量同构，所有云端记录归属 `user_id / _openid`。

### 5.1 核心表

```text
users                 用户：_openid, phone?, created_at, last_login_at

practices             功课：user_id, practice_id, name, display_name,
                      type, unit, alias, daily_target, vibrate_every,
                      show_on_home, sort, created_at, deleted, version

daily_archives        每日归档：user_id, date, practice_id,
                      ring_raw, phone_raw, manual_total,
                      target_snapshot, duration_min, times, version

adjustments           修正记录：user_id, adjustment_id, date, practice_id,
                      source(ring/phone), delta, created_at, tombstone

manual_entries        填报记录：user_id, entry_id, date, practice_id,
                      amount, created_at, tombstone

device_day_snapshots  戒指日快照：user_id, device_id, epoch, date,
                      practice_id, total, version

count_contexts        计数上下文：user_id, side(ring/phone), practice_id,
                      start_ts, round_count, reminder_target, version

vows                  大愿：user_id, vow_id, practice_id, name, target_total,
                      start_date, deadline?, existing_total?, status, version

devices               戒指：user_id, device_id, name, model, firmware,
                      battery, locked, practice_order, screen_mode,
                      last_sync_at, is_current, owner_token, version

settings              设置：user_id, ring_enabled, phone_enabled,
                      sound, theme, notice, version

sync_meta             同步元数据：user_id, since_token, last_sync_at
```

### 5.2 合并规则

1. 同一主键：`version` 新者胜、相同忽略、旧者拒绝。
2. 戒指日快照按 `(device_id, epoch, date, practice_id)` 覆盖，不追加。
3. 目标快照只写一次，永不覆盖。
4. 填报与修正用 tombstone 表达撤销，不物理删除。
5. 同步只更新 `ring_raw / phone_raw / manual_total` 等原始来源，不触碰修正记录。

## 6. 云函数 API

```text
authLogin             微信登录；创建或返回用户
bindPhone             绑定手机号（选做，不阻塞首版）
syncPush              批量上行：practice/archive/adjustment/manual/vow/device/settings
syncPull              增量下行：按 since-token 拉取
accountExport         导出用户全部数据
accountDelete         注销并删除云端数据（二次确认）
```

所有写操作必须：

- 校验用户身份。
- 校验主键。
- 比较 `version`。
- 写入服务端 `updated_at`。
- 返回新的 `since-token`。

## 7. 本地缓存与离线

小程序首次打开即可本地使用：

1. 未登录时，全部数据保存在本地缓存。
2. 用户登录后，本地数据首次全量上传。
3. 云端已有数据时，按 version 合并下行。
4. 断网时本地操作先入 `outbox`；联网后自动补传。
5. 小程序被销毁后，本地缓存仍在；下次打开继续同步。

## 8. BLE 模块规划

### 8.1 抽象接口

```javascript
connect(deviceId)
disconnect()
readDeviceState()
syncTime()
writePracticeList(list)
switchPractice({ practiceId, opId })
clearRound({ opId })
setReminderTarget({ target, opId })
startNewRound({ practiceId, reminderTarget, opId })
cancelReminder({ opId })
setLocked(locked)
setVibrationEvery(n)
pullSnapshots(cursor)
writeOwnerToken(token)
clearAllAndCreateEpoch(opId)
```

### 8.2 开发策略

- 先实现 `mock-adapter.js`：模拟一枚戒指，支持计数、快照、锁定、提醒。
- 小程序 UI 与同步逻辑全部先对 mock 开发。
- 真戒指固件就绪后，只替换 `wechat-adapter.js` 和设备协议细节，不重写页面。

### 8.3 核心流程

**绑定流程**

```text
搜索戒指 → 连接 → 读取设备状态 → 判断是否已有 owner_token
→ 无 token：写入新 token → 对时 → 下发功课 → 拉取快照 → 绑定完成
→ 有 token 且匹配：直接重连
→ 有 token 且不匹配：提示“已绑定其他用户” → 确认 → 清空并生成新 epoch → 绑定
```

**同步流程**

```text
连接 → 对时 → 读取设备状态 → 拉取增量快照
→ 小程序按主键覆盖保存 → 更新 daily_archives.ring_raw
→ 更新最后同步时间 → 断开或保持连接
```

**戒指侧开启新一轮**

```text
用户选择功课与提醒目标 → 生成 op_id
→ 一次性下发「切功课 + 清零 + 提醒目标」
→ 等戒指 ACK → 成功才更新 UI
→ ACK 丢失时用同一 op_id 重试，戒指不得重复清零
```

## 9. 开发阶段

### 第 0 阶段：项目初始化，0.5–1 天

- 创建原生小程序项目。
- 配置 ESLint / Prettier（可选）。
- 建立目录结构。
- 建立设计变量：字号、颜色、按钮高度、Tab 高度。
- 创建模拟数据。

### 第 1 阶段：本地业务核心，2–3 天

- practice / daily_archive / adjustment / manual_entry / vow / count_context 本地模型。
- 今日累积计算。
- 每日 0 点归档与补归档。
- 目标快照。
- 填报、撤销填报。
- 修正、撤销修正。
- 单元测试或纯逻辑测试页面。

**通过标准：** 不开 UI，也能用测试数据验证统计口径。

### 第 2 阶段：无戒指核心页面，4–6 天

- 今日 Tab。
- 手机计数页。
- 填报弹层。
- 功课详情、功课管理、添加功课、功课设置。
- 日历 Tab、当日详情、修正记录。
- 大愿列表、大愿详情、新建大愿。
- 计数汇总。

**通过标准：** 不绑定戒指也能完整使用。

### 第 3 阶段：账号与云同步，2–4 天

- 微信登录。
- 本地数据首次上传。
- 云端增量同步。
- 我的页登录状态。
- 设置页账号与云同步。
- 注销并删除云端数据。

**通过标准：** 删除小程序后重新进入并登录，历史完整找回。

### 第 4 阶段：戒指 BLE，4–7 天

- mock 戒指完整联调。
- 真实 BLE 搜索、连接、断开重连。
- 对时、下发功课、切换功课、锁定。
- 拉取日快照。
- 下发/取消提醒目标。
- 清空戒指并生成新 epoch。
- 多戒指数据结构验证。

**通过标准：** 用一枚真戒指或 BLE 模拟器完成定稿中的戒指验收场景。

### 第 5 阶段：联调验收，2–3 天

- 老年用户可读性检查。
- 断网、弱网、蓝牙断开、重复同步、跨零点。
- 真机 Android / iPhone 微信分别验证 BLE。

## 11. 首版验收清单

### 数据正确性

- [ ] 同一戒指快照同步多次，总数不变。
- [ ] 先收到新版本再收到旧版本，总数不倒退。
- [ ] 填报与撤销填报后，日历与大愿同步更新。
- [ ] 修正只减少戒指/手机来源，不能增加。
- [ ] 修改每日目标后次日生效，历史日期仍用旧目标快照。

### 小程序核心

- [ ] 未登录可本地使用。
- [ ] 登录后自动开启云同步。
- [ ] 删除小程序后重新登录，历史完整找回。
- [ ] 手机计数只影响手机上下文。
- [ ] 手机侧提醒目标明确标注“仅前台有效”。

### 戒指

- [ ] 戒指断开后仍继续计数。
- [ ] 重新打开小程序后能同步断连期间的计数。
- [ ] 戒指侧提醒目标断开手机后仍执行。
- [ ] 清空并重新绑定后，原用户已保存历史不减少。
- [ ] 指令 ACK 丢失后重试，不会重复清零。

## 12. 当前最重要的实现顺序

1. **本地业务逻辑与无戒指页面。**
2. **微信登录与云同步。**
3. **mock 戒指 BLE。**
4. **真实戒指联调。**

不要先做戒指页面美观，也不要先做营销页面。先把「数据正确」做出来。
